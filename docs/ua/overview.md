# Огляд проєкту

## Бізнес-призначення

Booking Application керує орендою конференц-залів. Клієнти можуть створювати, редагувати, видаляти та переглядати зали; шукати доступний зал за датою, часом і місткістю; бронювати його з додатковими послугами; отримувати розрахунок вартості й аналітику доходу.

## Основні можливості

- Каталог залів із назвою, місткістю, погодинною ціною, валютою та послугами.
- Пошук доступності, який виключає зали з бронюваннями, що перетинаються в часі.
- Підтвердження бронювання з ціною залу, доплатою за послуги, загальною сумою та валютою.
- Посторінкові списки залів і бронювань.
- Звіт із загальним доходом та аналітикою за залами.
- Автоматичне завершення прострочених бронювань через Quartz.
- Swagger/OpenAPI та версіонування API через URL.

## Ціноутворення

Бронювання має бути в межах одного календарного дня й інтервалу `06:00–23:00`. Неповні години оплачуються пропорційно. Якщо період перетинає тарифну межу, він ділиться на частини, кожна з яких розраховується окремо.

| Час | Модифікатор |
| --- | ---: |
| 06:00–09:00 | Знижка 10% |
| 09:00–12:00 | Базовий тариф |
| 12:00–14:00 | Націнка 15% |
| 14:00–18:00 | Базовий тариф |
| 18:00–23:00 | Знижка 20% |

Послуги оплачуються один раз за бронювання: проєктор `500 UAH`, Wi-Fi `300 UAH`, звукова система `700 UAH`.

## Запуск

Застосуйте [SQL-скрипти](../en/database-initialization.md) до віддаленої бази та налаштуйте `ConnectionStrings__Database` для runtime-користувача. Для необов'язкового запуску API/Seq у Docker:

```powershell
docker compose up --build
```

API доступне на `http://localhost:8080`, Swagger — на `/swagger`, Seq — на `http://localhost:8081`. База даних — віддалений SQL Server.

Для локального запуску з налаштованим віддаленим з'єднанням виконайте:

```powershell
dotnet run --project BookingApp.Services.Web
```

## Архітектура

Common містить бізнес-моделі, DAL readers заповнюють persistence entities, а AutoMapper перетворює їх на бізнес-моделі, Services має HTTP DTOs. Асинхронні процедури записують дані без EF tracking та IUnitOfWork. Типи провайдера залишаються лише в DAL.

`Services.Web` є коренем композиції та має явні посилання на всі рівні, тому вся реєстрація dependency injection залишається на межі застосунку. Докладніше: [Common](bll.common.md), [BLL](bll.md), [DAL](dal.sqlserverrepositories.md), [Service](services.web.md), [Тестування](testing.md), [Рефакторинг](refactoring.md).
