# Можливості понад вимоги завдання

Завдання вимагає створення, редагування й видалення залів, пошуку доступності, бронювання, тарифних правил, документації, безпеки та корисних звітів. Рішення додає наведені нижче можливості, щоб основний функціонал був практичним і придатним до розширення.

## Користувачі, ролі та дозволи

Domain та Infrastructure містять моделі `User`, `Role`, `Permission`, `RolePermission`, репозиторій і зіставлення EF Core. Початкове заповнення в середовищі розробки створює стабільного системного користувача та пов'язує його з роллю `Registered` і дозволами читання та запису залів і бронювань.

Endpoint бронювання зараз призначає бронювання попередньо створеному користувачу, оскільки реєстрація та автентифікація не входили до переліку потрібних методів API. Моделі готують систему до подальшої identity integration, але зараз **не** забезпечують авторизацію Endpoints. Перед використанням у промисловому багатокористувацькому середовищі потрібно додати автентифікацію та політики дозволів.

## Read Endpoints і посторінкове виведення

Окрім п'яти обов'язкових операцій, API надає деталі залу, посторінковий список залів і посторінковий список бронювань. Вони потрібні для адміністрування, отримання згенерованих ідентифікаторів і запобігають необмеженим відповідям із колекціями.

## Звіти й аналітика

`GET /api/v1/reports/bookings-summary` повертає загальну кількість бронювань, дохід, валюту та кількість і дохід у розрізі залів. Application обробляє дані обмеженими сторінками, а не завантажує всю таблицю в пам'ять.

## Автоматизація життєвого циклу

Бронювання мають стани `Reserved`, `Rejected`, `Completed` і `Cancelled` та доменні події. Фонове завдання Quartz знаходить завершені в часі активні бронювання обмеженими пакетами й автоматично переводить їх у стан `Completed`.

## Версіонування та документація API

Версіонування через URL (`/api/v1`) дозволяє майбутнім контрактам співіснувати. Swagger/OpenAPI генерується для версій у середовищі розробки, а кореневий URL перенаправляє на Swagger.

## Валідація та обробка помилок

FluentValidation і MediatR Pipeline централізують перевірку вхідних даних. Помилки Application та Domain використовують `Result`, а проміжне програмне забезпечення API формує контрольовані відповіді й не розкриває трасування стека.

## Спостережуваність

Serilog створює структуровані журнали запитів і застосунку. Docker Compose містить Seq, тому журнали можна шукати й аналізувати без додаткового налаштування. Handlers доменних подій журналюють життєвий цикл бронювання.

## Початкові дані та повторюваний запуск

Під час запуску середовища розробки система застосовує міграції та ідемпотентно створює ролі, дозволи, попередньо створеного користувача й три потрібні зали. Стабільний ідентифікатор користувача та згенеровані ідентифікатори залів забезпечують передбачувані локальні сценарії без жорстко заданих рядків бази даних у клієнтах.

## Розширена перевірка

Рішення розділяє Domain unit tests, Application unit tests, Application integration tests та API integration tests. PostgreSQL Testcontainers перевіряють реальні зіставлення та запити. Колекція у `test/Postman/` динамічно створює майбутню дату та унікальні назви, передає ідентифікатори й багаторазово перевіряє всі п'ять операцій API без ручної зміни даних.

## Операційна основа

Docker Compose надає API, PostgreSQL і Seq. Конфігурація розділена за середовищами, часові позначки зберігаються в UTC, а `IDateTimeProvider` дає змогу тестувати залежну від часу поведінку.
