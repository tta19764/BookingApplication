# Application

`BookingApp.Application` координує сценарії використання та не містить деталей HTTP або конкретної бази даних.

## Структура

- Commands змінюють стан: створюють, оновлюють і видаляють зали, а також створюють і змінюють бронювання.
- Queries повертають зали, доступність, бронювання та звіт.
- MediatR handlers залежать від доменних репозиторіїв, `IUnitOfWork`, `IDateTimeProvider` і доменних сервісів.
- FluentValidation перевіряє ідентифікатори, параметри посторінкового виведення, місткість, валюту, послуги та час до виконання handler.
- Pipeline централізує валідацію та структуроване журналювання.
- Записи відповідей і mappers формують стабільні моделі читання.
- Handlers доменних подій виконують прикладні побічні дії, зокрема журналювання.

## Створення бронювання

Handler завантажує зал, створює `DateRange`, відхиляє минулий час або перетин, передає розрахунок ціни та створення бронювання Domain-рівню, зберігає зміни через Unit of Work і повертає деталізацію вартості.

## Звітність

Query підсумкового звіту читає бронювання обмеженими сторінками, підсумовує кількість і дохід та групує результат за залами без завантаження всієї таблиці в пам'ять.

Handlers ізольовано перевіряються в `BookingApp.Application.UnitTests`, а з реальним збереженням даних — у `BookingApp.Application.IntegrationTests`.
