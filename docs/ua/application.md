# Application

`BookingApp.Bll` координує сценарії використання та не містить деталей HTTP або конкретної бази даних.

## Структура

- Публічні контракти `IBookingManager`, `IConferenceHallManager` та `IReportManager` оголошені в `BookingApp.Bll.Common`.
- Їхні реалізації розміщені в `BookingApp.Bll`, а рівень Services залежить лише від контрактів Common.
- Внутрішні запити й managers реалізують окремі сценарії та не доступні рівню Services.
- BLL managers залежать від інтерфейсів репозиторіїв, `IUnitOfWork`, `IDateTimeProvider` та абстракції розрахунку вартості.
- FluentValidation перевіряє ідентифікатори, параметри посторінкового виведення, місткість, валюту, послуги та час до виконання manager.
- Pipeline централізує валідацію та структуроване журналювання.
- Записи відповідей і mappers формують стабільні моделі читання.
- AutoMapperConfig централізує зіставлення між моделями Common, сутностями DAL і DTO рівня Services.

## Створення бронювання

Manager завантажує зал, створює `DateRange`, відхиляє минулий час або перетин, передає розрахунок ціни до `IPricingManager`, створює модель бронювання, зберігає зміни через Unit of Work і повертає деталізацію вартості.

## Звітність

Manager підсумкового звіту читає бронювання обмеженими сторінками, підсумовує кількість і дохід та групує результат за залами без завантаження всієї таблиці в пам'ять.

Managers ізольовано перевіряються в `BookingApp.Bll.UnitTests`, а з реальним збереженням даних — у `BookingApp.Bll.IntegrationTests`.
