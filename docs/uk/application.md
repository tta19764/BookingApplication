# Прикладний рівень

`BookingApp.Application` координує use cases та не містить деталей HTTP або конкретної бази даних.

## Структура

- Commands змінюють стан: створення, оновлення й видалення залу, створення та зміна бронювання.
- Queries повертають зали, доступність, бронювання й звіт.
- MediatR handlers залежать від доменних репозиторіїв, `IUnitOfWork`, `IDateTimeProvider` і доменних сервісів.
- FluentValidation перевіряє ID, pagination, місткість, валюту, послуги та час до виконання handler.
- Pipeline behaviors централізують валідацію й структуроване логування.
- Response records і mappers формують стабільні read models.
- Handlers доменних подій виконують прикладні побічні ефекти, зокрема логування.

## Створення бронювання

Handler завантажує зал, створює `DateRange`, відхиляє минулий час або перетин, передає розрахунок ціни та створення бронювання Domain-рівню, зберігає зміни через Unit of Work і повертає деталізацію вартості.

## Звітність

Booking summary query читає бронювання обмеженими сторінками, агрегує кількість і дохід та групує результат за залами без завантаження всієї таблиці в пам'ять.

Handlers ізольовано перевіряє `BookingApp.Application.UnitTests`, а з реальною persistence — `BookingApp.Application.IntegrationTests`.
